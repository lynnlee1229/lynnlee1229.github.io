WGS84, longitude first

Inputs follow the longitude/latitude convention of RFC 7946. This edition accepts 2D Point, Polygon and LineString features in a FeatureCollection. Convert other coordinate systems before importing; a legacy crs member is rejected. MultiPolygon, altitude, antimeridian geometry and global extents are outside this edition.

The plot auto-fits the input with a local equirectangular view and a latitude-based horizontal scale. It is a coordinate plot without basemap tiles. Point-in-polygon uses planar segments in degrees, so inputs are restricted to a regional extent of at most 30° per axis. This is not an area, navigation or cadastral measurement tool.

Boundary and topology

Point location uses ray crossing plus a point-to-segment tolerance of approximately 10⁻¹⁰ degrees. Exterior and hole edges are boundaries. A toggle determines whether boundaries count as membership. Overlapping polygons may produce multiple matches.

Validation rejects unclosed or zero-area rings, self intersections, repeated adjacent vertices, holes crossing the exterior, overlapping or nested holes, duplicate feature IDs and invalid coordinates. Validating the permitted subset is not a full implementation of every GeoJSON or OGC geometry rule.

Trajectory review, not ground truth

Distance is spherical haversine distance using radius 6,371,008.8 meters. Speed divides distance by the timestamp interval. The Earth is approximated by a sphere; no road network or ellipsoidal inverse solution is used.

An isolated spike candidate has two adjacent segments above the threshold and a bridge below it. Adjacent candidate spikes are not automatically removed. Endpoints are retained. A preview is a proposed review artifact; it does not overwrite the input or establish a correct trajectory.

Input and output limits

Browser inputs are limited to 2 MB, 10,000 features, 20,000 total positions, 200 polygons, 20 rings per polygon and 600 positions per ring. A join is limited to 1,000,000 candidate pairs and 100,000 output pairs. Split larger inputs into smaller regions. The visible result table is limited to 500 rows.

All computation runs in this tab. The site loads its static assets but has no data upload endpoint, map-service calls, analytics SDK or persistent file storage. Download the result to keep it. Geometry and synthetic inputs are checked against the fixed test suite before publication.

Further reading

RFC 7946 is the primary reference for GeoJSON. For larger local spatial SQL work, see DuckDB-Wasm’s spatial extension support. This Lab uses its own small geometry engine and does not embed DuckDB.
