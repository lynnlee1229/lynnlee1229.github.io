U1. 先核对坐标约定

先读: Automating GIS processes (AutoGIS) · Lesson 2 · Map projections
Handling coordinate reference systems in Geopandas

预测: 米制投影、看似合理的经纬度颠倒、跨日期线输入，范围校验分别能发现什么？

运行 U1，检查七种拒绝输入与仍可通过范围校验的 [24,60]、[60,24]。私有 PROJ 练习将 EPSG:3067 转为 EPSG:4326，并核对米制往返结果。

再改一个条件: 在工作台导入 islands.geojson，给 Feature 加 crs 后分析；移除 crs，再交换一个点的轴序。改标签不能代替重投影。
核对预期行为
CRS 成员与跨日期线范围被拒绝；合理数值的轴序颠倒仍可能通过，必须核查元数据。
有私有源码访问权限时的等价命令:
node labs/geo/run-exercise.mjs coordinates
U2. 外环、孔洞与边界谓词
先读: Automating GIS processes (AutoGIS) · Lesson 3 · Point-in-polygon queries
How to check if point is inside a polygon? / shapely geometries
预测: [1,3] 位于孔洞边缘，它在内部、外部还是边界？covers 与 contains 会怎样不同？
运行 U2，再检查 [-1e-11,3] 与 [1e-11,3]，对照单独记录的 GEOS 反例。
再改一个条件: 打开群岛工作台，设点 [1,3] 并切换边界开关，再移到 [4,4]；区分几何位置与是否计入命中。
核对预期行为
孔洞边缘为边界，孔洞内部为外部；两个 1e-11 探针都落入 Lab 容差带，GEOS 则区分内外。
有私有源码访问权限时的等价命令:

U3. 一个 ID 的多个分量
先读: Automating GIS processes (AutoGIS) · Lesson 1 · Shapely and geometry objects
Multipolygons; Validity of geometries
预测: 另一个分量孔洞里的 [2,2]–[3,3] 小岛能否属于同一要素？包围盒内的间隙是否命中？
运行 U3。原创群岛包含三个严格分离分量和一个孔洞；对比重叠、嵌套、共边与点接触的分量。

独立 oracle：一致结果与边界
保存的运行实际执行了 Lab JavaScript 与独立 Shapely 2.0.6 / GEOS 3.11.4。5 个区域几何覆盖多分量、孔洞、斜边三角形、凹形与反向环；2,735 次位置判断没有非预期差异。十五个手工推导案例先与 GEOS 核对，再比较 JavaScript。这是有限合成语料的证据，不是通用正确性证明。
反例明确保留：x=±10⁻¹¹、y=3 时，Lab 都报告边界，GEOS 分别报告外部与内部。本版保留 10⁻¹⁰ 度数值容差。点接触多分量在 GEOS 中可以有效，但本实现采用更严格的子集并明确拒绝。这些结果不能证明地籍精度或 GPS 准确度。
关联结果与 GEOS covers / contains 一致（7 / 4 对）。仅包围盒误收孔洞和间隙，仅第一分量漏掉三个覆盖点。十六种无效或不支持输入被拒绝，记录区分拓扑无效与格式、区域范围限制。

1. 在边界上放一个点
载入合成样例，region-a 含一个孔洞，region-b 与它重叠。在围栏模式中点击坐标图，或直接填写经纬度。可分别试 [114.3, 30.59]（region-a 内部）、[114.3, 30.61]（孔洞内部）、[114.28, 30.60]（外边缘）。
切换“包含边界”后，几何位置仍报告为“边界”，是否命中则随策略改变。孔洞内部属于外部，孔洞边缘属于边界。环的顺逆时针方向不影响本站的位置判断。
2. 把观测点关联到区域
切到空间关联。包含边界时，样例中有三个点命中，产生四个点面关联对；重叠区域中的点会同时命中两个面。排除边界后，边缘点不再命中，剩下三个关联对。
导出的 GeoJSON 会为每个 Point 添加 lab_matches 数组，包含全部命中；原有属性及其他要素保留。表格最多显示 500 对，导出包含全部计算结果。
3. 实际测量预过滤
工作台下方的固定种子基准会生成 1,500 个点与 36 个面，种子为 42，比较全部点面扫描和包围盒预过滤。两者共用相同的精确点面判断，并核对关联列表完全一致。
每种方法先预热一次，再交替顺序测量五次。展示耗时中位数，包含输入校验。精确判断次数表示减少的计算工作；实际耗时取决于浏览器、设备、几何形态和系统负载，预过滤并不保证对所有输入都更快。
4. 检查轨迹中的孤立跳点
切到轨迹检查。LineString 需要在 properties.timestamps 中为每个坐标提供一个严格递增、包含时区的 ISO 时间。样例的第 2 号点是孤立跳点；阈值为 120 km/h 时，两侧线段均超速，而从第 1 号点直接连接第 3 号点的速度合理。
复核预览会略去这个孤立候选点。琥珀色为原轨迹，青色虚线为预览。先检查被标记的线段，再决定是否导出；超速可能来自真实出行、时间错误或坐标错误，这个启发式方法无法判定真实原因。
5. 使用自己的数据
从已有 GIS 流程导出 WGS84 GeoJSON FeatureCollection，为要素填写明确的 ID，方便回溯关联结果。导入文件或粘贴 JSON，选择实验后点击“分析输入”。
轨迹需要在 properties.timestamps 中为每个坐标填写一个带时区的时间。复核后下载结果；关闭标签页后不会保留文件。全部操作都能在浏览器完成，不需要安装、地图账号或 API key。
