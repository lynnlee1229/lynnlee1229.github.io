Incident Detective is a browser game about reasoning from incomplete operational evidence. Six authored, consistent incidents are inspired by public synthetic experiments. None are private company incidents or real player telemetry.

The investigation loop

  1. Read the objective. Separate the symptom from the mechanism. There is no countdown.
  2. Spend credits on logs, metrics, plans or configuration. Each file is charged once. Evidence cannot be refunded; opening every file plus the probe will exceed the budget.
  3. Keep multiple hypotheses on the working board. Your markings are your own notes, not an automated diagnosis.
  4. Predict a causal relationship, then unlock the verification bench. Compare one changed variable with the baseline. Repeats are free. The first prediction is sealed.
  5. File a mechanism, an action and up to three acquired citations. An explicit “insufficient evidence” is available. Submission reveals the explainable debrief and full evidence archive.
  6. Reset a case to restore its budget; the best score remains. Clear all progress to remove saved data. Switch languages without changing the case deep link.

The six probe models

  • Join: choose a saved public strategy. Compare all output partitions and the exact count/weighted-sum oracle. No timing speedup is fabricated.
  • Pool: 18 arrivals at t=0,2,…34 ms, two workers, 60 ms fixed service, FIFO queue, immediate rejection when full. This omits JVM scheduling and I/O variability.
  • Deadline: 240 ms ideal work, 40 ms caller timeout. Work exits at 40 ms only with both propagation and cooperation; otherwise at 240 ms. No remote side effect is executed.
  • Counter alignment: error and completion counters must share window and scope. An invalid quotient is not an interpretable rate.
  • Locks: the fixed same-order schedule has B → A; opposite order reaches a cycle and resolves one victim. Holder scope is 8,020 ms with the call inside, 20 ms when moved before BEGIN. This is a model, not an actual SQL execution.
  • Retries: persistent failure, 12 logical requests, inclusive attempt limits. Attempts = min(12 × outer × inner, global cap), with no cap treated as infinity. Jitter changes timing, not count. A global cap does not model fairness.

Privacy and accessibility

The game makes no API calls and accepts no personal text, logs or files. Progress saving is off by default. Enabling it stores only predefined choices, acquired file IDs, probe parameters and scores in localStorage on this site’s origin. Language editions share this optional save. Storage is not encrypted and anyone using this browser profile can clear it. A blocked or corrupt save falls back to in-memory play.

Every control works with Tab and Enter/Space. Selects use arrow keys; no dragging, hover-only actions, timers, audio or color-only verdicts are required. A skip link, visible focus, reduced-motion support and textual chart counts are provided.

These cases deliberately have inspectable fixture solutions. Browser-delivered JavaScript can be inspected; private source repository visibility does not make game answers secret. No player data is sent to a server.
