EXPERIMENT 01

等待如何形成环。

A 更新 a，B 更新 b。A 请求 b 并等待；观察者在真实锁等待表看到 A → B 后，才允许 B 请求 a。InnoDB 选择一个事务回滚。同顺序对照仍会等待，但两个事务均提交。

EXPERIMENT 02

同一事务，两种读取规则。

A 先普通读取 100，建立读视图。B 将该行改为 200 并提交。A 再普通读，再 FOR UPDATE，再普通读。A 在此期间不修改该行。

隔离级别首次普通读B 提交后普通读锁定读再一次普通读
READ COMMITTED100200200200
REPEATABLE READ100100200100

两种隔离级别的锁定读都看到 200，并阻塞 B 随后改为 300 的写入，直到 A 提交。RR 下之后的普通读仍看到原来的 100。本实验只检验主键精确行读取，不能推广到间隙锁、幻读、DML 或 SERIALIZABLE。

A: START TRANSACTION;
A: SELECT value FROM a WHERE id=1;             -- 100
B: UPDATE a SET value=200 WHERE id=1; COMMIT;
A: SELECT value FROM a WHERE id=1;             -- RC: 200 / RR: 100
A: SELECT value FROM a WHERE id=1 FOR UPDATE;  -- 200 in both
A: SELECT value FROM a WHERE id=1;             -- RC: 200 / RR: 100
B: UPDATE a SET value=300 WHERE id=1;          -- waits for A
A: COMMIT;                                  -- B can finish
EXPERIMENT 03

查看计划，也检查实际执行。

固定种子 20261113。比较全表扫描、联合索引、覆盖投影及月份表达式改写。每组比较以结果哈希验证等价，耗时仅代表此次机器实测。

客户端耗时 / 中位数 ms

每种查询 1 次预热、7 次实际取回结果采样。共享暖缓冲池，不清缓存。固定顺序，无随机交叉设计。p95 为最近秩法，仅 7 个样本。

明确比较的边界

所有方案返回相同的 55 个 ID 和日期。full_scan 与 composite_noncover 还读取 amount_cents；覆盖投影有意省略该字段。composite_cover 与 expression_month 的完整结果一致。

InnoDB 二级索引包含主键。因此 (tenant_id, status, created_at) 可覆盖 id 与 created_at，但无法覆盖 amount_cents。在此数据中，DATE_FORMAT 比半开日期范围需要筛选更多索引候选行。

SQL

SELECT id,created_at,amount_cents FROM events WHERE tenant_id=7 AND status='paid' AND created_at>='2026-10-01' AND created_at<'2026-11-01' ORDER BY created_at,id
