Topology and conditions

etcd 3.6.6 · Darwin arm64 · Python 3.11.2

Three loopback voting processes, separate WAL directories, one host. Actual process kill/pause and delayed HTTP responses. No packet partition, storage destruction or multi-host performance measurement. Durations use the orchestrator’s monotonic clock and include request round trips.

A · Leader crash and quorum loss

The acknowledged pre-crash value survives and the restarted member catches up. One unavailable follower still permits a successful write. With two followers paused, both write and default read return no success inside their deadlines. Inspect the eventual value of the unknown write separately.

C · Lease expiry and stale writer

A is paused until the leased lock is observed absent. B obtains a larger create_revision and writes first. A resumes: plain mode accepts its stale value; fenced mode rejects it and retains B-current.

What remains unmeasured

These checks establish the asserted outcomes in this bounded schedule, not universal correctness or production capacity. Recovery uses the same durable directory; backup restore is not executed. The history workbench uses synthetic fixtures and does not certify these records. Raw logs remain local; this report contains only selected synthetic observations.
